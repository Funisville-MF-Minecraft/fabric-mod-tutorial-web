## What this site covers

This project is built for the Fabric ecosystem: not just client-side modding, but server-side modding, public server hosting, and Bedrock players joining a Java server through Geyser and Floodgate. In other words, this is not a minimal starter page for a single item or block. It is a complete learning path that tries to move from absolute beginner to someone who is capable of shipping real mods, operating a production server, and understanding why some ideas work on Java Edition while Bedrock players must follow a separate compatibility route.

Fabric's appeal is that it is intentionally lightweight. The loader is smaller, the API surface is easier to reason about, and the project structure tends to guide you toward clear separation between mod logic, assets, and server behavior. The trade-off is that you need to learn the right building blocks: Java, Gradle, Loom, mappings, event systems, data generation, and how the game server keeps world state authoritative. This site is designed to teach those fundamentals in a practical order, starting with the basics and moving toward operations, economics of server hosting, and Bedrock bridging.

## Why this site exists

A lot of modding docs stop at "here is how to register an item" or "here is how to make a block" and never cover the long tail of real-world work. The missing topics are often the ones that matter most to a mod author or server operator: Java version management, resource pipelines, dedicated server deployment, compatibility with Bedrock players, and how to think about the server as a production service instead of just a game client.

This site tries to fill that gap. It is meant to help someone go from a blank workspace to a running dev environment, then from a basic mod to a live server, and then from a live server to a public-facing multiplayer environment that can accept Java and Bedrock players with the right setup.

## Recommended path

1. Read the [What is modding?](/fabric-mod-tutorial-web/about/what-is-modding/) overview.
2. Follow the [Quickstart](/fabric-mod-tutorial-web/start/quickstart/) to set up a working mod project.
3. Move into the [Server basics](/fabric-mod-tutorial-web/server/basics/) section before you publish anything live.
4. Use the [Bedrock overview](/fabric-mod-tutorial-web/bedrock/overview/) page before you open the server to mobile, console, or Windows Bedrock players.
5. Use the [server hosting guide](/fabric-mod-tutorial-web/server/hosting/) when you are ready to move beyond local play and toward a real public setup.

> Tested on: Minecraft 1.21.1, Fabric Loader 0.16.x, Fabric API 0.115.x, Loom 1.7.x–1.8.x, Geyser 2.4.x.

## Local dev and hosted deployment

This project works both as a local documentation site for writing and previewing pages and as a public website that can be deployed to GitHub Pages or a similar static host. The same content source can be used in both settings because Astro builds a static site for deployment. That makes the docs useful for local iteration and for an official public home for the project.

If you are running a local preview, use `npm run dev`. If you are preparing a public release, use the built static output and publish it to a static host or GitHub Pages. The project is designed to support both flows, and the repository includes a deployment workflow to make the production path straightforward.
