# Bedrock overview

Fabric mods do not run on Bedrock clients. Minecraft: Bedrock Edition uses a different protocol, different networking stack, and a different codebase than Java Edition. That means a Bedrock player cannot simply install a Java Fabric mod and join a Java server in the same way a Java player does.

## If you only own Bedrock

You do not need to own Java Edition or ask a sibling to set up a Java modding environment just to understand the architecture. The important thing is to understand that Bedrock players join a Java server through a compatibility bridge, and the server must be configured to speak the Java protocol correctly.

If you are Bedrock-only, your useful path is usually:

- learn what a Java server is and why it matters
- understand how Geyser and Floodgate sit in front of the Java server
- check whether a public server supports Bedrock properly before joining
- focus on server compatibility, permissions, and login rules instead of Java-side mod development

This site is still relevant to you because the server-side rules and Bedrock translation layer are the parts that matter most for a real Bedrock-connected experience.

## The supported route

The practical path is Geyser plus Floodgate. Geyser bridges the Bedrock protocol to the Java server, and Floodgate helps Bedrock users join without a Java account or with extra compatibility handling for login flows.

## Java vs Bedrock

The most important difference is that Java Edition and Bedrock Edition are not just different clients. They are fundamentally separate game implementations. The item IDs, entity logic, GUI behavior, and redstone semantics are not the same, even when they appear similar to a player.

This matters for mod and server design. A server-side-only mod that uses vanilla mechanics usually works better with Bedrock than a mod that depends on Java-only client rendering or custom GUI systems. Bedrock players also interact with the server in a way that is not exactly the same as Java players.

## What works

- Vanilla-like server rules and mechanics
- Commands and simple gameplay modifications
- Server-side data and inventory rules that don't rely on custom client assets
- Bedrock players using a Geyser connection to the Java server

## What does not work

- Client-side Java mods that change rendering or input
- Custom Java assets or GUI flows that require a Java client mod
- Bedrock-specific behavior that cannot be translated through the Geyser bridge

## Tested on

Bedrock compatibility depends heavily on version pairs and bridge configuration. This overview is intentionally cautious. Tested on: Minecraft 1.21.1, Geyser 2.4.x, Fabric Loader 0.16.x.

## Version notes

Geyser and Floodgate update often, and Bedrock compatibility is not a static guarantee. Some features work across versions while others require a matching Java server and a known-good bridge configuration. Always verify the active bridge and server version pair before telling users their setup is fully supported.
